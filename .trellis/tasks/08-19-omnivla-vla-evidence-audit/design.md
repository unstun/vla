# Design: OmniVLA vision-language-action evidence audit

## 1. Scope and claim boundary

This child task audits two already pinned deployment candidates:

- OmniVLA-original on `gpu40901`;
- OmniVLA-edge on the Jetson AGX Orin 64GB.

It produces evidence for human review. It does not decide that either model is
a working VLA, validate navigation, calibrate the trajectory for Lite3, or add
any robot-control edge.

## 3. Evidence model

The audit separates four questions that must not be collapsed:

1. **Identity:** Are the source, weights, preprocessing, modality, and action
   head the pinned artifacts?
2. **Code path:** Do visual bytes and language tokens reach computation that
   contributes to the returned trajectory?
3. **Observed sensitivity:** Does changing one input while holding the other
   fixed change the trajectory beyond repeat-run variability, and is the change
   semantically plausible?
4. **Action meaning:** Is the output an action-level local trajectory rather
   than a label or prose string, and what downstream calibration/control remains
   absent?

Passing identity or code-path inspection alone is not enough. Sensitivity alone
also does not prove reliable navigation.

## 5. Data flow and contracts

```text
pinned image + exact instruction
  -> model-specific pinned preprocessing
  -> resident pinned model and action head
  -> raw normalized 8 x 4 trajectory
  -> immutable per-run JSON record
  -> shared metrics/overlay generator
  -> static human-review page
```

Each run record must include:

- schema version and run ID;
- model/source/checkpoint identities;
- image ID, SHA-256, dimensions, and transformation provenance;
- exact instruction and prompt wrapper;
- repeat index and random/determinism settings;
- raw finite `8 x 4` trajectory without rounding;
- modality ID and available preprocessing/action-head metadata;
- cold-load, preprocessing, forward, postprocessing, and wall timing when
  observable;
- process exit, warnings, and failure reason;
- `actuation_enabled: false`.

One decoder/validator owns this JSON contract. Analysis and HTML generation may
not reinterpret raw fields independently.

## 6. Analysis

The shared analysis computes, without deleting failures:

- exact/repeat equality and per-element repeat dispersion;
- mean absolute, root-mean-square, and maximum absolute trajectory difference;
- endpoint `(x, y)`, path length, signed lateral displacement, and heading;
- between-prompt and between-image differences relative to repeat dispersion;
- pre-registered semantic observations: left/right sign tendency, forward path
  tendency, and whether `stop` reduces motion relative to `move forward`.

No single invented scalar threshold decides "VLA". The page must show raw
values, repeat variability, expected direction, and violations side by side.

## 7. Human-review artifact

Generate a static local page at:

`review/index.html`

It must contain:

- a visible `AI-prepared evidence; human decision required` banner;
- one identity and code-trace card per model with file/line anchors;
- the frozen matrix and exact hashes;
- side-by-side image, prompt, trajectory overlay, and raw/derived metrics;
- repeat variability versus counterfactual variability;
- a failure gallery that is not hidden behind a pass filter;
- a claim matrix separating `surveyed`, `imported`, `reproduced`, `integrated`,
  and `validated`;
- three unselected human decision boxes: `sufficient evidence`,
  `insufficient evidence`, and `revise and rerun`.

Use plain static HTML/CSS/JavaScript only if interaction materially helps
inspection. Do not introduce a frontend framework.

## 8. Safety and non-interference

- No MotionSDK, ROS publisher, `/cmd_vel`, joint sender, UDP robot-control
  sender, autostart entry, or locomotion import may be added.
- Input images are existing retained fixtures; do not reconfigure or seize the
  live camera.
- All remote model processes are bounded by timeouts and stopped after the
  batch.
- Before and after each remote batch, record task PIDs, listener ports, GPU/RAM
  use, and relevant source hashes. Do not kill unrelated processes.
- On any identity mismatch, non-finite output, malformed record, unexpected
  control dependency, or missing sync-back artifact, stop and mark the affected
  model panel failed.

## 9. Rollback

Rollback removes only the new task-owned remote directories and local generated
work copies. The pristine source, existing checkpoints, previous experiment
evidence, other Jetson content, and sibling repositories remain unchanged.

## 10. Review boundary

The implementing agent returns local files and a diff but does not commit,
archive the task, or declare the VLA question resolved. The current primary
window independently checks the artifacts and presents them to Dr Sun.
