## Acceptance

1. Exact Foxy interfaces build on ARM64; pluginlib loads actual plugins.
2. Stock NavigateToPose -> ComputePathToPose -> FollowPath reaches a goal in the
   labelled flat kinematic fixture; cancel stops output.
3. PCT coordinates, layer selection, requested XYZ/yaw and map identity survive
   planning; disconnected/invalid/late worker replies fail closed.
4. Mission binding requires an exact acknowledgment. New owners wait for prior
   measured stop. Stale or mismatched commands cannot reach the actuator topic.
5. Costmap uses completed native map evidence and original source timestamps;
   stale evidence is not made current by publication. No second raycast mapper.
6. Native and simulated checks are reported separately. Full Newton stair,
   Jetson receive-only and authorized physical walking are separate gates.

Normal-load measurements and deliberately injected faults are separate attempts.
Dropping observations changes map evidence and requires obstacle-retention tests.
The 250 ms observation and 100 ms body/native-validation limits are not loosened
to improve a benchmark result. The prior 5 Hz map profile is not assumed suitable.

## Execution and retention

Local source is authoritative. Build/run only in an owned ARM64 Foxy container,
with outputs in a fresh temporary directory. Return compact logs, configuration,
hashes and findings locally. Archive bulk evidence on gpu5070ti and verify it
before cleaning owned temporary files/containers. No GPU training or robot motion.
The pre-existing Git index lock and staged v34/v35 records remain untouched.
