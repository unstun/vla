v196/v198-v202 and replaces only `lite3_nav2_bridge`, `lite3_nav2_plugins` and

## New default launch

```bash
ros2 launch lite3_nav2_bridge navigation.launch.py \
  terrain_manifest:=/absolute/terrain/terrain.json \
  native_planner_config:=/absolute/native.yaml \
  backend_config:=/absolute/backend.json \
  generated_params:=/absolute/new-profile.yaml \
  base_frame:=base use_sim_time:=true
```

`terrain_manifest` replaces `pct_map_bundle`. The launch generates a SCAN config
with static input paths and source identities from the manifest and supplies its
PCT file to the native planner. One `static_terrain` node replaces the three old
static publishers. Keep `/pct_tomogram`, `/pct_ground_surface`, and
`/pct_physical_floor` distinct. They remain real SCAN inputs, unlike the internal
LocalMotion observation topics removed in step 3.

The clock gate is unchanged: publish once after two advancing positive samples,
and republish after a backwards/reset clock. Without simulated time the same
gate uses the node clock and cancels its one-time publication timer afterwards.
All clouds retain the original layout and 3 cm publisher Z offset; SCAN's matching
Z subtraction is unchanged. PCT body-reference height remains a separate value.

Local/global Nav2 maps have one disabled input-free placeholder layer, a 1x1 grid, 1 Hz updates and no grid
publication. A nonzero rate is required by Foxy's activation wait. Foxy cannot parse an empty YAML plugin array, so its stock ObstacleLayer is
disabled with no observation sources or footprint clearing. These are
lifecycle/TF shells, not collision maps. LocalMotion's 2D projection timer is
removed, and the new plugin library no longer builds TerrainLayer. Native SCAN
3D inflation, support/geometry checks and async mapping remain unchanged.
The unused Wait recovery server is gone; the BT's 1 Hz global planning child
remains for step 5.

`native_graph.py` is the matching Building geometry-sensor graph adapter. Its
explicit `--terrain-manifest` argument replaces scene-dependent static publisher
branches. It pins the v198 telemetry bridge and inherits v196 observation/input
helpers. It is source/component checked only; no new physical graph was run.
