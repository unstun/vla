一条路线如何变成可执行的局部曲线

  1. PCT 返回含高度的 world Path首次规划固定 canonical goal；后续刷新不得偷偷改变终点。
  2. Controller 判断目标与几何是否变化同几何且当前有曲线时只更新参考；需要时发布 /pct_path。
  3. SCAN 建立内部参考曲线与局部前沿这里的 global_data 是参考轨迹表示；局部窗口只有有限规划范围。
  4. 局部候选经搜索、优化和几何检查已有曲线可作为热启动；过期、缺失或多次失败改用实测里程计起点。
  5. 发布含时间原点的三次样条控制器按轨迹相位采样，再转换为机体系速度；原地转向可冻结执行相位。
MAP CONTRACTS

不能笼统叫作“地图”的四种东西

  1. PCT 全局分层代价长距离可达性；固定 map.pickle，包含支撑覆盖修正。
  2. 静态地面与物理表面区分地面高度、真实表面存在和可通行性；保留不同来源身份。
  3. SCAN 实时 3D 局部地图点云、位姿与静态支撑融合；0.05 m 栅格，异步不可变快照。
  4. Nav2 身体高度的二维切片由 C 导出，接 TerrainLayer / InflationLayer；不回写 A 的 PCT 全局地图。
一个层面的“可行”只是该层合同成立，不能自动推出下一层也可行。

状态分布在多个拥有者中

修改前先确定状态由谁维护、谁能失效它、谁来恢复。下面的场景是基于代码的事件示意，不是运行日志回放。

四层状态，各自负责自己的终态

任务身份 / MissionBridge + Nav2

request_id、goal_id、current_owner、canonical_goal_pose、action 状态；负责是否还是同一个任务。

局部可行性 / SCAN FSM

INIT → WAIT_TARGET → GEN_NEW_TRAJ ↔ EXEC_TRAJ ↔ REPLAN_TRAJ；另有 EMERGENCY_STOP 与 fail_safe 恢复。

轨迹执行 / Controller + Tracker

当前样条、exec_time、waiting_for_spline、goal_braking、execution_frozen；负责眼前是否有可执行命令。

身体与关节 / V12 + stance

RL、STAND_SETTLING、STAND_TRANSITION、FIXED_STAND、REJOIN；最终 PD hold 由实验 driver 另行验证。

三类时间，不能互相替代

ROS / 原生物理仿真时间

位姿、点云、样条 start_time、几何新鲜度与最终站立持续时间。导航节点使用 use_sim_time；通信桥的发送与超时另用 monotonic。

Mac 与 Linux monotonic 时间

局部求解节拍、指令源时间、通信超时、实际耗时。跨主机要估计偏移与不确定度，失同步会置零。

局部轨迹执行相位

接收时对齐样条时间原点，后续增量推进；转向或终点对齐会冻结相位，并把 freeze 反馈给 SCAN。

navigation_contract.json 保留了历史 version=v59。频率字段是配置意图；实际调度与时钟语义以当前代码、生成参数和运行记录为准。

后续修复的最小审查单位：一条跨层合同

  1. 先选定一个原始失败事件：保留输入、状态、版本、时钟、地图 revision 和加载库。
  2. 说明改动所属模块，以及它会让哪些下游状态失效；一次只改变一个可解释的行为。
  3. 回放既有成功案例、失败案例和负例；局部通过后再做完整路线重复，并保留原二进制对照。
  4. 分别报告组件通过、单次到达、重复可靠性、实际停车和性能；不把它们压成一个 PASS。

行为恢复后的规则现在由谁负责
终点与朝向第一次成功路线的末点锁定为终点；明确给朝向就采用，包括 0；未给朝向则取路线最后有效方向。后续刷新保持整个终点位姿。C++ RoutePolicy，归属于 Nav2 的 PCT 插件
旧路线保留同一任务遇到原有三类规划失败，或进入原有终点接近范围，返回最后有效路线。取消或换任务隔离缓存；不扩大允许回退的错误类型。导航层缓存；实时几何与支撑检查仍由 SCAN 完成
普通失败重试规划或跟踪普通失败：Wait 1 秒，最多重试 6 次。站稳超时：直接失败，0 次重试。原 Nav2 RecoveryNode；通过准确的 FollowPath 动作身份识别站稳超时

任务入口只补传“任务身份、是否省略朝向”的开始／结束消息，不参与逐次规划。PCT 算法、局部规划策略、避障参数和重试预算保持原样。

  • 异步地图快照。规划读取明确 revision，地图更新由单独写入方维护。
  • V12 与 PD 站立控制。本轮不碰行走策略权重。

从默认运行链删除什么

  • PCT 服务绕回 MissionBridge。任务入口不再装载地图、运行规划器、缓存路线。
  • SCAN 外露的第二套任务恢复决策。保留算法内部尝试和紧急制动，任务重试交给 Nav2。
  • 插件直接发 Twist、服务端再绕开发布的双套接口。统一恢复标准“计算返回、服务端发布”。
  • 没有算法消费者的 2D 地形切片与膨胀计算。移出默认闭环，Nav2 必要的 TF／生命周期设施保留。

PCT 迁移的具体落点：直接复用 OfflineElePlanner 的 InitMap、Plan 和 SetReferenceHeight。原包装层含额外 Z 偏移，而当前 MissionBridge 实际用优化器高度覆盖了它；迁移必须保留这一实际语义，身体参考高度只加一次。终点与取消归属留在 Nav2 任务上下文，不把整套 jobs 字典搬进规划插件。

本次恢复不引入“明显偏离”的新阈值，不改全局刷新条件，也不把局部堵塞变成新的全局策略。

未来 VLA 仍保留平级路线来源的位置。接入方式和刷新策略另行决定；本轮不改 PCT 的代价图，不加动态堵塞掩码。

完成：上层只收到一种最终答案

规划→行走→站稳确认→完成

位置和朝向到达作为内部制动状态；FollowPath 保持运行，现有 GoalChecker 继续等待站稳；通过后才结束整个任务。

进入终点制动后，暂停行走 ProgressChecker，采用单独的站稳截止时间。取消和失败沿同一任务通道传播。GoalChecker 连续确认 FIXED_STAND、关节已由 PD 接管和实测低速度 2 秒才成功。取消或新目标重置该窗口；站稳超时作为不可重试的终局失败，绕过普通 FollowPath 的 Wait/重规划恢复分支；不能由笼统 RecoveryNode 再走一遍路线。

外部测试脚本负责观察和断言，不再成为完成任务不可缺少的控制环节。
