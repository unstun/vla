# SCAN Resubmission Failure And Integration Pitfalls

Archived at 2026-09-16 21:32 America/Los_Angeles. Stage: experiment + analysis.
Task: `09-16-emos-harnessvln-reimplementation`.

## Incorrect Endpoint Derivative In The Frozen SCAN Implementation

The first accepted continuous pilot was followed by three failed resubmissions
in display-OFF, software-RViz and GPU-RViz conditions. The captured chain is:
cancel reached `WAIT_TARGET`; a new PCT route entered `GEN_NEW_TRAJ`; SCAN rejected
refined trajectories at the unchanged acceleration check; no new spline reached
the controller; the service raised `initial_heartbeat_missing` and completed a
protected stop. A later generation-cancel rejection is a consequence of that
stop, not the initiating defect. See the
[display result](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/pointcloud_display/RESULT.md)
and the [GPU trial native planner log](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/pointcloud_display/runs/pointcloud_20260916T173400Z_rviz_gpu/returned_artifacts/logs/scan_planner_node.log).

The frozen manager samples the polynomial only while `t < time`, then passes
`gl_traj.evaluateAcc(t)` as the terminal derivative. For the failed-resume
fixture, the true end is 1.7307008405 s but the last sample is 1.6 s. The sampled
acceleration is 1.778131330 m/s^2; the true endpoint acceleration is approximately
zero. Refinement stretches the spline from 1.6 to 3.563376137 s but retains the
wrong boundary derivative, leaving 1.778376817 m/s^2 against the 1.5 m/s^2 gate.
This is a defect confirmed in the implementation frozen for this experiment;
its origin has not been traced to an unmodified official upstream release.
Source: [planner manager](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/p2b_execution/builds/scan_03/src/plan_manage/src/planner_manager.cpp),
polynomial sampling and derivative construction around lines 150-171.

A fresh native `SCANPlannerManager::reboundReplan` process with an empty grid
reproduces the failed input 3/3 times without cancellation, a controller, Isaac,
sensors or GPU load. The native warning reproduces
`acceleration at t=3.500 is 1.567 > 1.500` at printed precision. Thus cancellation
is not necessary for this rejection; the stopping position exposes it. The
previous successful resume was about 5 cm away and supplied 1.477623507 m/s^2,
just below the same threshold. Evidence:
[diagnostic result](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/scan_replan_diagnosis/RESULT.md)
and [four derived fixtures](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/scan_replan_diagnosis/inputs/cases.json).

The isolated candidate changes only `evaluateAcc(t)` to `evaluateAcc(time)`.
All four fixtures, each repeated three times with seed zero, pass. The failed
resume's refined sampled maximum acceleration falls to 0.590244562 m/s^2.
Neither acceleration limits nor heartbeat deadlines are relaxed. Original
and candidate input gates each matched 67 native source files, 380 installed
files and 15 package files; each return matched 16 artifact hashes.
[Comparison](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/scan_replan_diagnosis/comparison.json)
passes nine checks; [independent review](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/scan_replan_diagnosis/independent_review.json)
supports the mechanism and limited claim.

Production was not changed. The candidate still fits the original sampled
points and ends approximately 3.5 cm from the failed fixture's route endpoint.
Endpoint geometry, nonempty-map collision checking, random initialization,
later replans and a continuous Isaac cancel/resubmit episode remain required
before adoption. A passing planner return is not whole-stack navigation
validation. Preserve original failures and use new immutable run IDs.

## ROS Transport Can Fail Across Otherwise Healthy Processes

Earlier P2B integration remained stationary because the service did not receive
odometry. Two separate defects were verified: the service subscription needed
the bridge's `BEST_EFFORT` sensor QoS; and the split ROS containers needed
`--ipc=host` in this host environment. A separate CPU transport comparison had
zero delivery with isolated IPC and fresh delivery with host IPC, both using
effective domain 94 and localhost-only networking. Working processes and
matching topic names were insufficient evidence of transport delivery.
See [P2B corrections and retained failures](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/P2B_RESULT.md).

## Display Performance And Navigation Acceptance Must Be Separated

NVIDIA rendering and NVENC recording succeeded while the navigation test
failed. Relative to OFF, the one GPU-display run had +2.786% wall time per
simulation second and +363 MiB sampled active-card memory peak, with no
telemetry drops. All conditions include a stationary protected tail, and
recording overhead is included. These observations do not establish dense-map,
long-duration or statistically repeatable performance, nor reliable navigation.
Whole-host CPU did not decrease in this single comparison; no high GPU
saturation claim is supported. See the [measured comparison](../../../.pipeline/experiments/2026-09-16_pi_cortex_harnessvln/pointcloud_display/gpu_comparison.json).
