# Newton 实时目标、闭环数值、测量与冻结回执陷阱

归档：2026-10-01；调查/实验：2026-09-30；阶段：实验与分析。本次无新 Trellis 任务。实验根目录为 `.pipeline/experiments/2026-09-26_newton_stair_reproduction/`。以下只记实际验证的结果；未取得根因的故障不补写猜测。提交号见主会话归档回执。

## 1. 组件小于 33.3 ms 仍不能推出完整系统 30 Hz

- 现象：v44 两个记录回放仅 11.7588 / 12.7634 ms，v45 实跑 local 却 16.8619 Hz、median 42.2256 ms、625 超时、684 跳周期。
- 已验证原因/边界：实际同步轮次包含多个不同初值或缩短参考前缀的搜索/优化尝试；878 个完成轮中，647 轮首个 seed 搜索失败，736 轮用短 prefix 后成功。140 单尝试轮平均 19.6697 ms，其中 21 超预算；630 双尝试轮平均 56.4666 ms，其中 524 超预算。迟到后调度器跳过槽位。未观察到 A* 200 ms timeout，也无同模式同初值完全重复；两个 legacy 模式参数虽传入但在 graph initializer 未使用。
- 禁止推论：不同尝试数受场景难度混杂，不能用 19.7 ms 平均值保证优化后 30 Hz；日志搜索时段包含打印与检查，非独立 CPU profile。电脑硬件性能不足、全由日志造成、无意义重复重试均未证实。
- 接续：`audits/2026-09-30_local_30hz_opportunities/{findings.json,PLAN.md,rounds.json}`。窗口复用、旧轨迹初值、共享时间预算、跨回调纯 raw 缓存/输出 profile 尚未实现，需独立整数版本并保留最新碰撞/PVA/地形门。

## 2. CUDA 图快不等于闭环数值合格

- 现象：v38 CUDA 求解器图约三倍于原 CPU，RTF 约 1.58，但继续闭环时轨迹/关节分歧；naive CUDA eager 也未提速。
- 已验证：固定目标重放避免新的策略反馈，输入 200 个已记录目标完全相同；位置最大差 0.000325229 m 达 1 mm 门，关节最大差 0.007906556 rad 未达 0.001 rad 门。确证“当前 CUDA 路径不满足预设数值门”，未取得该误差更细的数值求解根因。
- 处理：不放宽门、不把 CUDA 采用成已保真；v40 CPU 图的 200 行闭环逐位精确与逐步检查通过后才采用 CPU 图。证据 `audits/2026-09-30_gpu_device_compare/target_replay_comparison.json`、`versions/v40/RESULTS.md`。只保留核函数提速又去掉逐步容量/力/有限值门不是本次做法。

## 3. 冻结 harness 父文件名错误不能通过改历史掩盖

- 现象：v39/v44 测试回执的旧几何比较字段 false，与实际逐字段几何一致冲突。
- 已验证原因：harness 查父目录不存在的 `geometry.json`，真实 v36 attempt09 父文件是 `<fixture>/result.json`；返回 child `*_geometry.json` 与真实父 JSON 完全相等，SHA-256 也分别一致。
- 处理：保留冻结 harness 及 false 结果；在 v41 / v45 `component_qualification.json` 另存实际路径、两个完整 JSON 比较和哈希修正。后人须读取修正而不能只摘旧布尔字段，也不能重写 frozen 版本来“修齐”记录。

## 4. raw 与 gated 命令频率不可混测

- 现象：v42 观测约 30.00554 Hz，但没有 raw controller 频率记录。
- 已验证原因：raw observer 使用 Twist，实际 publisher 消息为 P2BStampedTwist，故 raw 订阅不匹配。gated Twist 还包含额外停止发布，不能替代控制定时器频率。
- 处理：v45 修正 actual raw 类型，测得 29.9647549 Hz；global 用 52 次唯一实际 PCT 计算测得 0.9999814 Hz。来源两次 `runs/*/recording_measurements.json` 与对应版本 observer，后续保留环节、消息类型、时钟与样本身份。

## 5. 录像墙钟 1:1、时钟一致和仿真实时是不同门

- 现象：最终 30 FPS 视频按真实墙钟播放仍同时记录 local 16.86 Hz 和 native/wall RTF 0.94；起身/导航合并账会使 RTF 比较口径变化。
- 已验证原因：v46 只 causal 选择原始记录帧，零物理步，57.033333 s 编码跨度与 57.022285 s 实际墙钟相差 11.05 ms；它不能改变 v45 仿真速度。v40 物理-only 图回放余量不足以证明覆盖整套 sensing/transport/native solver 开销；v42 起身总账 RTF 0.844749、导航口径 0.890032。
- 处理：v45 在原 factory 结束后单独锚定导航墙钟，不重置真实 native 状态/时间；原始起身仍保留，物理步骤不丢。分别报告 clocks、native/wall RTF、控制/local/global 实测 Hz、编码 FPS。证据 `versions/v46/timeline_check.json`、v42/v45 timing records。macOS 沙箱无 NSScreen 的渲染失败尝试保留，图形渲染升级权限后通过，不能把失败尝试当已出片。

## 6. 录制成功不是路线成功，global 无路故障仍未定位

- 现象：v45 supervisor exit 0、视频与 copyback 可用，但终态是 `FAILED: global_refresh_failed:pct_no_route`。
- 已确认边界：实际 PCT refresh 返回无路径导致原停止流程，未完成 Building 路线。停止/copyback 与返回文件 SHA 核验通过仅证明证据归档完成；导致 PCT 无路的具体地图/路线根因尚未取得。
- 接续：`runs/v45_realtime_preview01/recording_measurements.json` 与原返回日志；全局无路必须单独诊断，不可把局部提速当该问题已修复。v3 一次 12 m 空地仍是最后导航验收，v42/v45 失败不得丢弃。
